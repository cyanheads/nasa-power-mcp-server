# 0.4.0 — 2026-10-28

## Added

- **`nasa-power-guide` agent skill** — `skills/nasa-power-guide/SKILL.md`, served over MCP as `skill://nasa-power-guide/SKILL.md` (plus the `skill://{+path}` template) through `createApp({ skills })` (mcp-ts-core 0.13.18). It covers which tool answers a typical-month versus a dated question, grid-cell size, data freshness, rate versus total units, degree days, the one-data-call-at-a-time gate, and SQL over staged tables. It ships in the npm package, the Docker image, and the `.mcpb` bundle.
- **Agent Plugins `plugin.json` and `mcp.json`** at the repo root (mcp-ts-core 0.13.18 template, [cyanheads/mcp-ts-core#426](https://github.com/cyanheads/mcp-ts-core/issues/426)) — the 1.0.0 manifest read by Codex, Cursor, GitHub Copilot, VS Code and Kiro, and a stdio `npx -y @cyanheads/nasa-power-mcp-server` entry with `MCP_TRANSPORT_TYPE=stdio`.
- **`add-skill` framework skill** for authoring published skills in root `skills/`.

## Changed

- **The `.mcpb` bundle** no longer carries the framework's build-only files (its `changelog/`, `config/`, `scripts/`, `templates/`, `CLAUDE.md`, `AGENTS.md`) (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#791](https://github.com/cyanheads/mcp-ts-core/issues/791)). The bundle cleaner and `lint:packaging` select agent docs only at a dependency package's root, so the MCP SDK's runtime `dist/ext/skills/` modules stay in the bundle ([cyanheads/mcp-ts-core#794](https://github.com/cyanheads/mcp-ts-core/issues/794), ported locally with `tests/scripts/mcpb-agent-docs.test.ts`).
- **`.mcpbignore`** uses root-anchored entries and now also excludes `/changelog/`, `/.claude-plugin/`, `/.codex-plugin/`, `/plugin.json`, `/mcp.json`, `/CLAUDE.md`, `/AGENTS.md`, `/.dockerignore`, `/.gitattributes` and `/devcheck.config.json`; root `skills/` ships.
- **`package.json` `files`** gains `skills/`, and the **Dockerfile** copies `skills/` into the production image.
- **`lint:packaging`** also validates the root `plugin.json`/`mcp.json` pair and the published `skills/` tree; `check-skills-sync` identifies framework skills by frontmatter only.
- **README getting started** is restructured: a hosted-endpoint `claude mcp add` line, an `npx` install, one generic JSON config, and the Docker run command against the published image; the clone-and-install steps move under Local development. A Skills section lists `nasa-power-guide`.
- **Bug report form** replaces five separate fields with one Environment table.
- **`bunfig.toml`** `minimumReleaseAge` drops from 3 days to 1 day (`@cyanheads/mcp-ts-core` stays excluded).
- **Framework skills**: 17 updated to the mcp-ts-core 0.13.18 versions.
- **`tests/config/startup.test.ts`** links `skills/` into its scratch directory so the bundled entry finds it; `CLAUDE.md`, `AGENTS.md` and `docs/design.md` describe the published skill and the DuckDB 1.5.6 hold.

## Fixed

- **HTTP memory growth under Bun** — the HTTP transport no longer retains about 71 KiB per request through its shutdown signal, so sustained HTTP traffic no longer grows memory until the process runs out. 0.3.0 shipped on mcp-ts-core 0.13.16, and the Docker image runs under Bun (mcp-ts-core 0.13.17, [cyanheads/mcp-ts-core#786](https://github.com/cyanheads/mcp-ts-core/issues/786)).
