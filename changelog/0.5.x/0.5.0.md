# 0.5.0 — 2026-11-23

## Added

- **`nasa_power_get_design_conditions`** returns POWER's ASHRAE-style heating, cooling and extreme design conditions for one point from the Climate Indicators API, in metric units with optional `startYear` and `endYear`; `nasa_power_list_reference` topic `coverage` gains a `design_conditions` row ([#41](https://github.com/cyanheads/nasa-power-mcp-server/issues/41)).
- **`deferredLocations`** on `nasa_power_compare_locations` output (optional): locations left uncompared, exactly as sent, ready to send as `locations` in a second call. It is present only when locations were deferred ([#40](https://github.com/cyanheads/nasa-power-mcp-server/issues/40)).

## Changed

- **Breaking: `possibleSharedGridCell`** on `nasa_power_compare_locations` is `{ parameters, locations }[]`, previously `string[][]`: sites whose series match exactly for every listed parameter, grouped per parameter because solar and meteorology use different grids ([#37](https://github.com/cyanheads/nasa-power-mcp-server/issues/37)). The per-parameter entries enlarge the response: a comparison within about 150 characters of the 40,000-character inline budget now stages (canvas on) or is refused with `canvas_required` and a split (no canvas).
- **Breaking: a column alias or CTE spelled exactly like a DuckDB internal metadata view** (`duckdb_tables`, `pg_class`, `sqlite_schema`, and 33 more) in `nasa_power_dataframe_query` is refused with `system_catalog_access`; 0.4.2 answered it. Rename the alias.
- **`nasa_power_compare_locations`** accepts 2–20 `locations`, up from 2–10, and compares the first 10 per call (the first 9 when 11 arrive); `request`, `failed` and `possibleSharedGridCell` cover the compared sites ([#40](https://github.com/cyanheads/nasa-power-mcp-server/issues/40)).
- **`invalid_window`** refusals state the range in force, and `nasa_power_get_climatology` and `nasa_power_compare_locations` climatology years must span at least two calendar years, refused before any data request. The configuration is fetched before the parameter dictionary ([#38](https://github.com/cyanheads/nasa-power-mcp-server/issues/38)).
- **`invalid_correction`** for `PSC` or `WSC` on `nasa_power_get_region` names the point-only tools and the substitute parameter (`PS`, `WS10M`, `WS50M`) ([#38](https://github.com/cyanheads/nasa-power-mcp-server/issues/38)).
- **`nasa_power_dataframe_query`** returns up to `rowLimit` rows (capped at 1,000) whatever their size, and `nasa_power_dataframe_describe` returns every table's provenance; the `query_limit` reason is gone from both ([#36](https://github.com/cyanheads/nasa-power-mcp-server/issues/36)).
- **SQL gate** answers `range()` and `generate_series()` with constant arguments. A quoted `pragma_*` call is refused as `denied_function` and a file read as `sql_read_only` (was `missing_table`).
- **Rate-limited errors** carrying `retryAfter` show `retry after <value>` in the error trailer.
- **Bun floor** moves from 1.4.0 to 1.4.4.

## Fixed

- **Error text** from every tool is plain `path: value` lines; `content[]` no longer shows escaped code fences around upstream messages. A retry-exhausted failure, including a body read that stalls or is cut, keeps the last attempt's code and message and reports `retryAttempts` as its own field ([#39](https://github.com/cyanheads/nasa-power-mcp-server/issues/39)).
- **`pg_am`, `pg_tablespace` and `pg_collation`**, referenced bare in `nasa_power_dataframe_query` SQL, returned engine rows and are now refused with `system_catalog_access` like the other metadata views.
- **Summary staging:** `nasa_power_get_timeseries`, `nasa_power_get_climatology`, `nasa_power_get_region` and `nasa_power_compare_locations` stage their summaries when the observations fit neither inline nor as a one-row preview, instead of refusing with `dataset_limit`.
- **Expired retry clock** returned an internal-label timeout message and now returns "NASA POWER call deadline exceeded.".
